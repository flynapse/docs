## 2. Planner decisions recorded for the owner's plan review

| # | Decision | Rationale |
|---|---|---|
| D1 | The 10% "head sampling" of fetch/XHR spans is implemented as a deterministic **trace-id-ratio drop at export time** (`RatioDropSpanProcessor` in `lib/telemetry/sampling.ts`) with the SDK sampler `AlwaysOnSampler`, so every outgoing `traceparent` carries the sampled flag. | Spec §3.3 pins the server to `parentbased_traceidratio 1.0`; a true head-sampled browser would send `traceparent` with flag `00` on 90% of requests and the backend's parent-based sampler would drop 90% of server traces for browser-originated requests. The drop processor uses `TraceIdRatioBasedSampler(0.1)` on the span's own trace id, so the retained set is deterministic per trace; CLIENT spans with `ERROR` status or `http.response.status_code ≥ 500` are always kept; CLIENT spans that are children of a browser span (the chat turn's SSE request) ship with their parent. Vitals and errors are never sampled. Owner may veto; the fallback is a real head sampler plus a backend `always_on` rule that cannot distinguish browser traffic. |
| D2 | The OTLP exporter is bespoke (`lib/telemetry/exporter.ts`) over the JSON serializers of `@opentelemetry/otlp-transformer` (`JsonTraceSerializer`, `JsonLogsSerializer`); the upstream `@opentelemetry/exporter-trace-otlp-http` / `exporter-logs-otlp-http` (both verified at 0.222.0) are **not** adopted and the trace exporter dependency is removed. | Spec §7.4 requires posting through the authenticated fetch helper; the upstream browser exporters use XHR/`sendBeacon` with static headers (no Cognito refresh, no 4xx classification, no bounded queue with eviction). The serializers give the exact OTLP/JSON wire shape the collector's `otlp` receiver accepts. |
| D3 | Ingest route selection is by **token presence at send time** (`getToken() !== null` → `/logging/ingest/v1/<signal>` through `fetchWithAuth`; otherwise `/logging/public/ingest/v1/<signal>` through plain `fetch`), not by the page the event was created on. | The old client captured `isPublicPage` per event and re-queued private batches until authenticated (a second wedge). Token presence is the question the public/authenticated split actually asks (`lib/auth/public-paths.ts:81-98`), and it is decided when it matters. The `isPublicPageForLogging` consumer entry for `lib/logging/logger.ts` in `tests/unit/auth/public-paths-single-source.test.ts:50` is removed at cut-over. |
| D4 | `lib/telemetry/events.ts` is created before the 4.1 gate with only the spec-named baseline members (`browser.web_vital`, `browser.error`, `browser.log`, `browser.telemetry.dropped`) and the envelope; every other catalogue member is added after the gate (F7). | Spec §7.4 names vitals and errors as baseline; the rest is the owner-reviewed list (ruling 6). |
| D5 | `TelemetryProvider` is mounted in F4 (outermost provider in `AppProviders`); the legacy `LoggingProvider` keeps `initializeLogging()` but loses `initializeFrontendTracing()` in F4, and is deleted in F10. Until master 5.5 lands, exports to the not-yet-existing `/v1/<signal>` sub-paths answer 4xx and are dropped and counted. | The branch is not deployed before F10; mounting early lets F5–F9 be verified in `npm run dev` against the counter and the in-memory harness, and keeps one fetch instrumentation active at a time. |
| D6 | Product facts are sent with the six allow-listed wire names (`document_opened`, `document_closed`, `session_started`, `session_ended`, `clarification_answered`, `upload_finished`); the catalogue's `product.*` labels are documentation only. Rulings 15/16 are applied to research 07: #14 and #21 become product facts (P); `browser.upload.started` (#13) stays an OTel log record; `browser.log` `info`/`debug` never ship. | Spec §7.2 allow-list; rulings 15, 16. |
| D7 | `session_ended` may be emitted more than once per `session_id` (once per `pagehide`, plus once on sign-out/identity change); the session id persists across reloads so a reload is an unload without a new `session_started`. | Browser cannot distinguish reload from close at `pagehide`; the alternative (idle timers) does not run in a closed tab. Consumers take the last row per `session_id` (open question 3 for Stream P). |
| D8 | Chat-turn milestones are threaded explicitly: `startChatTurn` returns a `ChatTurnHandle` passed through `performRequest` into `runChatStreamRequest`, which wraps `apiClient.sendMessageStream` in `turn.runInContext` and marks `init`/`step`/first-token from the SSE handlers. | Concurrent turns exist (page chat and `CopilotDock`), so a module-level "current turn" would misattribute; wrapping at the call closest to the `fetch` makes the SSE request span a child of the turn span regardless of earlier awaits (attachment uploads). |
| D9 | The `logger` wrapper keeps the legacy call signature (`(msg: string, ...args: unknown[]) => void` for `debug/info/warn/error/fatal`) so the 73-file repoint at cut-over is import-only; `useLogger` (zero call sites) and `setUserId` (dead) are not carried; server-side (route handlers under `app/api/*`) the wrapper writes to `console` only (SSR telemetry deferred, spec §3.4). The wrapper reads `isDevelopment()` from `lib/runtime-config` directly, never `lib/config` (which imports the logger — a cycle). | Ruling 16; research 02 §1.1 server-branch finding. |
